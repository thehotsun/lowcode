## 改动内容（共 2 个文件）

**1. 新建拦截脚本 `C:\Users\Admin\.zcode\hooks\git-guard.js`**（目录不存在则创建）

- 从 stdin 读取 ZCode 传入的工具调用 JSON，取 `tool_input.command`
- 命中 git 写操作时打印原因并**退出码 2**（PreToolUse 的 deny），放行则退出码 0；JSON 解析失败放行（不阻断正常工作）
- 拦截清单：`commit / push / merge / rebase / reset / revert / cherry-pick / pull / tag / stash / branch / checkout / switch / restore / clean / rm / worktree`（含 `git -C <path> commit`、`git add && git commit` 链式写法）
- 放行：`git status / log / diff / add / fetch` 等只读与暂存操作，以及一切非 git 命令——不影响我正常帮你构建、跑测试、看代码

**2. 合并写入 `C:\Users\Admin\.zcode\cli\config.json`**

- 先完整读取现有配置（可能已有 mcp、plugins 等），仅在顶层**合并** `hooks` 字段，绝不覆盖其他内容
- 结构：`hooks.enabled: true`（配置文件钩子默认禁用，必须显式开启）+ `PreToolUse` 事件 + matcher `Bash`（区分大小写正则，匹配工具名）+ `type: "process"`（`command: "node"` + args 指向脚本，不走 shell，Windows 最稳）+ `timeoutMs: 5000`

## 验证（三步，全部只读/无害）

1. 脚本级：向脚本管道注入样例输入，断言 `git commit -m x`、`git push`、`git -C d:\x reset --hard`、链式 `git add -A && git commit` 均退出码 2；`git status`、`node xxx.js`、`npm run build` 均退出码 0
2. 配置级：读回 config.json 确认 JSON 合法、hooks 字段正确、原有内容未丢失
3. 实战级：让我执行一次无害的 `git commit --dry-run`——若钩子已生效会被拒绝（预期结果）；若本会话未热加载（钩子配置可能需重启会话生效），dry-run 也不会产生任何提交，我会如实报告生效状态
